# TECH.md

## Architecture

Single-page Next.js App Router application. All S3 operations flow through the `S3Manager` component (`components/s3-manager.tsx`), which orchestrates credential state, bucket selection, object listing, and CRUD operations. The `AssetTable` component (`components/asset-table.tsx`) handles display, preview, download, copy URL, rename, and delete UI.

**Entry point**: `app/page.tsx` → `S3Manager`

## Tech Stack

| Layer | Technology |
|-------|------------|
| Framework | Next.js 16.0.10 (App Router) |
| UI | React 19 + Tailwind CSS v4 |

## API Endpoints

All endpoints are under `/api/s3/*`. Credentials are passed inline (query params for GET, JSON/form-data body for others). No session/auth — credentials are per-request.

| Method | Endpoint | Purpose |
|--------|----------|---------|
| GET | `/api/s3/objects` | List objects with pagination (`bucket`, `prefix`, `continuationToken`, `maxKeys`) |
| POST | `/api/s3/objects` | Upload file (multipart form: `file`, `key`, `bucket`, credentials) |
| DELETE | `/api/s3/objects` | Delete object (JSON body: credentials + `bucket` + `key`) |
| PUT | `/api/s3/objects` | Rename object (copy + delete, JSON body) |
| PATCH | `/api/s3/objects` | Generate presigned download URL (1-hour expiry, 3600s) |
| GET | `/api/s3/presigned-url` | Generate presigned URL (1-hour expiry, 3600s) |
| POST | `/api/s3/buckets` | List/create buckets |
| POST | `/api/s3/test` | Test S3 connection |

## Public URL System

- **Format**: `https://nos.jkt-1.neo.id/{bucket}/{encoded-key}`
- **Generated by**: `components/s3-manager.tsx:getPublicUrl(bucket, key)`
- **Applied to**: `S3Object.previewUrl` AND `S3Object.imgUrl` — both always contain the permanent public URL
- **Copy URL buttons** in `components/asset-table.tsx` use `obj.imgUrl \|\| obj.previewUrl` — always resolves to the public URL
- **Uploads** use `ACL: 'public-read'` (`app/api/s3/objects/route.ts:196`) so objects are publicly accessible via direct URL
- **No presigned URLs in frontend**: The frontend never fetches or uses presigned URLs. Presigned URL API endpoints exist for potential private object access.

## Security Model

- Credentials stored in `localStorage` only (`lib/s3-storage.ts`), never in code or Git
- All S3 operations proxied through Next.js API routes — credentials never exposed to browser console network tab as direct S3 calls
- `forcePathStyle: true` on all S3 clients for S3-compatible service compatibility

## File Structure

```
app/
  page.tsx              → Renders <S3Manager />
  layout.tsx            → Metadata, fonts, Analytics
  api/s3/               → All S3 proxy API routes
    objects/route.ts    → CRUD + presigned download (GET/POST/DELETE/PUT/PATCH)
    presigned-url/      → Presigned URL generator (GET, kept for private access)
    buckets/route.ts    → Bucket list/create
    test/route.ts       → Connection test
components/
  s3-manager.tsx        → Main orchestrator, credential state, public URL logic
  asset-table.tsx       → Object display, preview, copy URL, download UI
  upload-dialog.tsx     → Upload form
  delete-dialog.tsx     → Delete confirmation
  create-bucket-dialog.tsx
  bucket-selector.tsx
  credentials-form.tsx
lib/
  types.ts              → S3Credentials, S3Object, Bucket, PaginatedResponse
  s3-storage.ts         → localStorage credential persistence
  upload-rules.ts       → File type/size validation
```
